# Member 4: Admin Manage Complaint

## 📌 Module Overview
This module is exclusively for system administrators. It provides operations to modify the status of existing complaints (Pending -> In Progress -> Resolved) or permanently delete them from the CRM.

## 🔗 Connections & Dependencies
- **Authentication**: Checks the role from the token (from Member 2). If the role is NOT 'admin', the action is rejected with `401 Unauthorized`.
- **API Route**: Hits `PUT /api/complaints?id=X` and `DELETE /api/complaints?id=X`.
- **UI Elements**: Injects "Edit" and "Delete" buttons inside the table rows generated by Member 5.

## 💻 Core Code Explanation

### 1. Backend Updates and Deletions (`backend_manage_complaint.go`)
Validates that the incoming request actually comes from an Admin, retrieves the `id` from URL query parameters, and executes the SQL command.
```go
// UPDATE LOGIC (PUT)
status := updateData["status"].(string)
_, err = db.Exec("UPDATE complaints SET status = $1 WHERE id = $2", status, id)

// DELETE LOGIC (DELETE)
result, err := db.Exec("DELETE FROM complaints WHERE id = $1", id)
```

### 2. Frontend Admin Modals (`frontend_manage_complaint.vue`)
Controls the Vue state for displaying modals (`showStatusModal` / `showDeleteModal`) and firing the REST endpoints.
```javascript
async updateStatus() {
    const res = await fetch(`${this.apiBase}?id=${this.selectedComplaint.id}`, {
        method: "PUT",
        headers: this.getAuthHeaders(),
        body: JSON.stringify({ status: this.newStatus }),
    });
    if (res.ok) {
        this.closeStatusModal();
        await this.fetchComplaints(); // Refresh data table
    }
}
```
